# StudyBenefits — бот геймификации учёбы для школьников

## Назначение решения

Часть школьников воспринимают оценки как формальность. StudyBenefits превращает
успеваемость из формальности в игру с реальными призами.

Решение — бот в мессенджере MAX, который:

1. Автоматически раз в сутки в 00:00 (по времени сервера) опрашивает электронный дневник (ЭСУО) каждого
   подключённого ученика.
2. Переводит оценки в опыт (XP): `5 → +50`, `4 → +30`, `3 → 0`, `2 → −30`, `1 → −50`.
3. Растёт уровень от 1 до 15 по формуле `XP(уровень) = 100·L² + 50·L`.
4. Открывает бонусы с промокодами от компаний-партнёров на пороге XP соответствующего уровня.
5. Даёт ученику самому забрать бонус одной кнопкой.

Роли в системе три: ученик (зарабатывает оценки в школе и получает призы), партнёр (заводит бонусы со своими
промокодами), администратор (одобряет заявки партнёров, выдаёт права).

Ключевое архитектурное решение — слой коннекторов: бота не нужно переписывать под каждую
региональную систему электронного дневника. Сегодня реализован `MockEgasConnector` 
(имитация для разработки и демонстраций), но добавить новую ЭСУО — 
это положить один файл в `connection/connectors/`.

## Основной пользовательский сценарий

Ученик: `/start` → согласие с пользовательским соглашением → регистрация → бонусы.
Данные для теста:
   - город - Волгоград
   - школа - Школа №1
   - остальные данные - любые валидные значения

1. Жмёт `/start`, выбирает роль «Ученик», принимает соглашение (PDF).
2. Проходит регистрацию по шагам: город → регион → школа → ФИО → класс →
   группа → логин ЭСУО → пароль ЭСУО. При нескольких совпадениях города в разных регионах 
   бот предлагает выбор кнопками. Пароль шифруется Fernet и кладётся в БД в зашифрованном виде.
3. В меню ученика три кнопки:
   - 📈 Мой прогресс — XP, уровень и визуальная шкала до следующего уровня.
   - 🎁 Мои бонусы — уже полученные промокоды.
   - 🎯 Доступные бонусы — бонусы, открытые по-текущему XP, с кнопкой
     «✅ Получить» под каждым. Промокод выдаётся только при достаточном опыте, до истечения
     срока и если он ещё не получен.
4. Каждую ночь в 00:00 (по времени сервера) бот сам обновляет XP по свежим оценкам и снимает бонусы, у которых
   истёк срок.

Партнёр подаёт заявку (тип → компания → предложение → контакты), после одобрения
администратором появляется кнопка «➕ Добавить бонус»: название → требуемый уровень (1–15) →
дата окончания → промокод.

Администратор видит «📋 Список заявок» и одобряет или отклоняет каждую карточку, а также
назначает новых администраторов по MAX ID.

scripts/     CLI: python -m scripts init|seed-base|seed-test|seed-admin|status

Бот работает в режиме long polling: `bot/main.py` вызывает `dp.start_polling(bot)`, а в
отдельной задаче крутится `services/daily_update` — ночное обновление XP. События идут через
`GET /updates`, поэтому наружу открывать порты не нужно.

## Схема данных PostgreSQL

Схема описана в нотации DDL

```sql
-- Субъекты РФ, города и организации
CREATE TABLE subject (
    id    INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name  VARCHAR(255) NOT NULL
);

CREATE TABLE city (
    id          INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        VARCHAR(255) NOT NULL,
    subject_id  INTEGER      NOT NULL REFERENCES subject (id)
);

CREATE TABLE educational_institution (
    id       INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name     VARCHAR(255) NOT NULL,
    city_id  INTEGER      NOT NULL REFERENCES city (id)
);

-- Электронные системы учёта оценок (ЭСУО)
CREATE TABLE EGAS (
    id         INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name       VARCHAR(255) NOT NULL,
    API_file   VARCHAR(255) NOT NULL 
);

-- Связь «учреждение ↔ обслуживающая его ЭСУО» (M:N)
CREATE TABLE EI_with_EGAS (
    EI_id     INTEGER NOT NULL REFERENCES educational_institution (id),
    EGAS_id   INTEGER NOT NULL REFERENCES EGAS (id),
    PRIMARY KEY (EI_id, EGAS_id)
);

-- Участники
CREATE TABLE student (
    id             INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    surname        VARCHAR(255) NOT NULL,
    name           VARCHAR(255) NOT NULL,
    patronymic     VARCHAR(255),
    grade          INTEGER      NOT NULL,  
    student_group  VARCHAR(255) NOT NULL,
    max_id         INTEGER      NOT NULL,   -- внешний идентификатор MAX
    login          VARCHAR(255) NOT NULL,   -- логин в ЭСУО
    password       VARCHAR(255),            -- Fernet-шифротекст, nullable
    experience     INTEGER      NOT NULL DEFAULT 0,
    EI_id          INTEGER      NOT NULL REFERENCES educational_institution (id)
);

CREATE TABLE admins (
    id      INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    max_id  INTEGER      NOT NULL            -- внешний идентификатор MAX
);

-- Партнёры и их бонусы
CREATE TABLE partner (
    id      INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name    VARCHAR(255) NOT NULL,
    max_id  INTEGER      NOT NULL            -- внешний идентификатор MAX
);

CREATE TABLE bonus (
    id               INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name             VARCHAR(255) NOT NULL,
    promocode        VARCHAR(255) NOT NULL,
    need_experience  INTEGER      NOT NULL,  -- порог XP = 100·L² + 50·L
    end_date         DATE,                   -- NULL = бессрочный
    partner_id       INTEGER      NOT NULL REFERENCES partner (id)
);

-- Выданные бонусы (M:N). ON DELETE CASCADE: удаление бонуса отзывает выдачу
CREATE TABLE student_bonus (
    student_id  INTEGER NOT NULL REFERENCES student (id),
    bonus_id    INTEGER NOT NULL REFERENCES bonus (id) ON DELETE CASCADE,
    PRIMARY KEY (student_id, bonus_id)
);

-- Заявки партнёров, ожидающие решения администратора
CREATE TABLE applications (
    id               INTEGER      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    max_id           INTEGER      NOT NULL,  -- идентификатор MAX заявителя
    type             VARCHAR(255) NOT NULL,  -- commercial | ou | esou
    partner_name     VARCHAR(255) NOT NULL,
    description      VARCHAR(255) NOT NULL,
    contact_details  VARCHAR(255) NOT NULL
);
```

Связи и кардинальность

| Отношение | Тип | Правило удаления |
|---|---|---|
| `subject` → `city` | 1 : N | `RESTRICT` (по умолчанию) |
| `city` → `educational_institution` | 1 : N | `RESTRICT` |
| `educational_institution` ↔ `EGAS` | M : N через `EI_with_EGAS` | `RESTRICT` |
| `educational_institution` → `student` | 1 : N | `RESTRICT` |
| `partner` → `bonus` | 1 : N | `RESTRICT` |
| `student` ↔ `bonus` | M : N через `student_bonus` | `CASCADE` по `bonus_id` |


## Требования к сертификатам

На машине, где запущен бот, должны быть установлены сертификаты удостоверяющего центра
Минцифры России (УЦ Минцифры / НУЦСМ) в системное хранилище доверия.


## Запуск одной командой

```bash
cp .env.example .env && docker compose up -d --build
```


## Необходимые параметры окружения

Перед первым запуском заполните `.env` (шаблон — `.env.example`):

| Параметр | Обязателен | Как получить |
|---|---|---|
| `MAX_BOT_TOKEN` | да | Токен бота в мессенджере MAX |
| `EGAS_ENCRYPTION_KEY` | да | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `ADMIN_MAX_ID` | да | MAX ID первого администратора (остальных он назначает сам) |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | нет | Дефолты `hackathon` / `hackathon` / `hackathon` |
| `POSTGRES_PORT` | нет | Дефолт `5432` |
| `DATABASE_URL` | нет | Только для запуска без Docker; compose подставляет `db:5432` сам |
| `TEST_PARTNER_MAX_ID` | нет | Только для тестового профиля, дефолт `1000000001` |


## Переменные окружения

| Переменная | Где читается | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | `bot/config.py` | Токен бота MAX. Без него приложение падает на старте |
| `EGAS_ENCRYPTION_KEY` | `services/crypto.py` | Fernet-ключ (44 символа) для паролей ЭСУО |
| `DATABASE_URL` | `db/database.py`, `docker/entrypoint.sh` | DSN SQLAlchemy вида `postgresql+asyncpg://user:pass@host:5432/db` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | `docker-compose.yml` | Реквизиты БД; попадают и в DSN, и в healthcheck `pg_isready` |
| `POSTGRES_PORT` | `docker-compose.yml` | Порт, публикуемый на хосте |
| `ADMIN_MAX_ID` | `scripts/seed_admin.py` | MAX ID первого администратора, `0 < id ≤ 2147483647` |
| `TEST_PARTNER_MAX_ID` | `scripts/seed_test_data.py` | MAX ID тестового партнёра (профиль `test`) |
| `DB_WAIT_SECONDS` | `docker/entrypoint.sh` | Сколько ждать готовности БД, дефолт `60` |

Внутри образа дополнительно выставлены `PYTHONUNBUFFERED=1`, `PYTHONDONTWRITEBYTECODE=1`,
`PIP_NO_CACHE_DIR=1`, `PYTHONPATH=/app`. Файл `.env` не попадает в образ (`.dockerignore`) и не
коммитится (`.gitignore`); в контейнер он приходит через `env_file`.


## Используемые порты

| Порт | Назначение |
|---|---|
| `5432/tcp` | PostgreSQL 16 (`${POSTGRES_PORT:-5432}:5432`) |

Бот HTTP-сервера не поднимает: long polling ходит в `GET /updates` наружу сам, поэтому входящих
соединений у него нет и публиковать порты не нужно.

Исходящие соединения: `platform-api2.max.ru` (мессенджер), `https://<домен ЭСУО>` (дневник).
