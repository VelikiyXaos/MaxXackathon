# Ежедневное обновление ЭСУО: назначение, реализация и прототипы

Документ описывает ежедневную задачу, реализованную в
`services/daily_update.py`, и функции, оставшиеся прототипами, — для
ревью тимлидом.

## Назначение

Каждый день в **00:00** выполняется:

1. **Опрос всех студентов в ЭСУО** на обновление оценок → пересчёт опыта.
2. **Проверка всех существующих бонусов** на истечение срока действия →
   отзыв просроченных.
3. **Обновление информации о доступных студенту бонусах** после
   обновления баллов.

## Как это устроено

Точка входа — `services.daily_update.daily_update_loop()`, запускается
задачей `asyncio.create_task(daily_update_loop())` из `bot/main.py`
вместе с ботом: цикл засыпает до ближайших 00:00, выполняет
`run_daily_update()`, повторяет. Ошибка прогона не убивает цикл.

Порядок шагов в `run_daily_update()`:

1. `update_all_students_grades()` — для каждого студента:
   `get_grade_provider()` → `provider.get_grades_count()` →
   `calculate_and_save_school_experience()`.
2. `expire_bonuses()` — `bonus_crud.get_expired()` → отзыв связей
   `student_bonus` у всех студентов через `student_bonus_crud.remove()`.
3. `refresh_available_bonuses()` — `grant_available_bonuses()` для
   каждого студента.

Шаги изолированы: ошибка одного студента или нереализованный прототип
не отменяют остальные шаги, всё попадает в `DailyUpdateReport.errors`
(отчёт: сколько студентов обновлено/упало, ΔXP, истёкшие и выданные
бонусы, список ошибок).

## Семантика опыта

Опыт — **абсолютное значение за текущий учебный год**:

- `calculate_and_save_school_experience()` записывает
  `experience = total_xp` (пересчёт по всем оценкам периода) и возвращает
  дельту;
- период считает `AbstractGradeProvider`: **с 1 сентября текущего года**
  по сегодня → **1 сентября опыт обнуляется у всех студентов**;
- ежедневный прогон идемпотентен: каждый день в 00:00 берутся новые
  оценки из ЭСУО и получается новый абсолютный балл, повторное начисление
  старых оценок исключено;
- обнуление устойчиво к простоям: в первый же прогон после 1 сентября
  период начнётся с 1 сентября текущего года.

Следствие: 1 сентября у студентов уровень → 0, а **уже выданные бонусы
сохраняются у них** — `grant_available_bonuses` только добавляет, обратной
логики нет; отзыв при обнулении опыта не требуется.

## Реализованные и недостающие функции

| # | Функция | Файл | Статус |
|---|---------|------|--------|
| 1 | `get_grade_provider(student_id)` | `connection/factory.py` | **реализована** |

### 1. `connection.factory.get_grade_provider` — реализована

Возвращает готовый к опросу провайдер оценок для студента:

1. `student_crud.get(student_id)` → `EI_id`, `login`, `password`;
2. `ei_with_egas_crud.get_egas_ids_for_institution(EI_id)` → id ЭСУО
   (у учреждения ровно одна, берётся единственная; пусто — `ValueError`);
3. `egas_crud.get(egas_id)` → `EGAS.API_file` — **название класса
   обработчика** этой ЭСУО (ЕГАС);
4. класс ищется в реестре `_HANDLER_REGISTRY`
   (`{"NetSchoolClient": NetSchoolClient}`), создаётся клиент с кредами
   студента и оборачивается: `EgasGradeProvider(client=client)`.

Неизвестный обработчик — `ValueError` с перечнем доступных. Новые
обработчики добавляются строкой в реестр.

### 2. `connection.egas_client.NetSchoolClient` — прототип

```python
class NetSchoolClient:
    def __init__(
        self, *, login: str, password: str | None
    ) -> None: ...
    async def login(self) -> None: ...
    async def logout(self) -> None: ...
    async def get_diary(
        self, *, student_id: int, date_from: date, date_to: date
    ) -> dict: ...
```

**Контракт:** `get_diary()` возвращает raw-JSON в формате netschoolapi —
словарь с ключом `"weekDays"`, который разбирает
`EgasGradeProvider._fetch_grades()`; структура совпадает с
`mock_egas.models.Diary.to_raw()` (пакет `mock_egas` из ветки
`EGAS_connector` подходит для тестов без реального сервера).

Транспортный слой (библиотека `netschoolapi` или собственный HTTP) и
адрес сервера ЭСУО — внутренняя деталь класса: контракт ответа зафиксирован
кодом провайдера, на систему выбор не влияет. Авторизация и запросы
дневника — `NotImplementedError` до реализации.

### 3. `db.crud.bonus.get_expired` — прототип

```python
async def get_expired(
    session: AsyncSession, *, date_now: date | None = None
) -> list[Bonus]: ...
```

**Контракт:** все бонусы с `end_date < date_now`; бонусы без срока
(`end_date IS NULL`) не истекают никогда.

**Реализация** (зеркально существующему `get_available()`):

```python
timestamp = date_now or date.today()
result = await session.execute(
    select(Bonus).where(
        Bonus.end_date.is_not(None),
        Bonus.end_date < timestamp,
    )
)
return list(result.scalars())
```

Истёкшие бонусы отзываются связью `student_bonus` — флага `is_active`
в модели нет, а `get_available()` уже отфильтровывает истёкшие по
`end_date`, поэтому после отзыва бонус просто перестаёт выдаваться.
Выданные студентам бонусы при этом сохраняются.
